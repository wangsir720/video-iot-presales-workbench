# video-iot-presales-workbench · 视频物联售前解决方案工作台

把一次视频物联项目的售前交付从"手工拼文档"变成"一条命令出整套方案"。

输入一个场景需求（点位、码率、留存天数、要跑的智能规则），输出一整套可交付的方案包：
**系统架构图 + 点位设计表 + 设备清单 BOM + 存储/带宽/PoE/算力测算 + TCO 对比 + POC 测试报告 + 技术标偏离表**。

> 个人学习项目，与任何厂商无关。机型为按公开通用规格抽象出的参数化档位，参数与价格为公开渠道档位参考值，正式项目以厂商正式彩页与报价为准。

---

## 一、要解决什么问题

视频物联项目售前阶段最耗时的不是讲产品，而是反复算、反复写：

| 痛点 | 常见做法 | 本项目的做法 |
|---|---|---|
| 存储/带宽靠经验估 | 手工按"大概 1 路 2T"拍脑袋 | 按码率 × 路数 × 天数实算，余量可调 |
| 点位与选型靠翻彩页 | 逐页对照参数 | 需求 → 评分选型矩阵，自动排序 |
| 方案书靠复制旧文档 | 改格式改半天，数字还对不上 | Jinja2 模板渲染，数字全部来自测算结果 |
| 架构图靠拖拽 | 改一次点位重画一次 | 架构图 as code，改配置重跑即出图 |
| 清单靠 Excel 手填 | 漏项、口径不一致 | BOM 由测算结果推导，含分组与小计 |
| POC 指标靠口述 | 无标注集、不可复算 | 规则引擎 + 标注集比对，指标可复跑 |

### 测算引擎

- **存储**：单路日录像量 = 码率 × 86 400 s ÷ 8；总容量 = Σ(单路日量) × 天数 × 1.15 余量。
- **带宽**：总码率 × 1.15，并按阈值给出接入/上联建议。
- **PoE**：设备功耗汇总后 ÷ 0.8，给交换机留 20% 余量。
- **边缘算力**：每路 4 TOPS × 1.15 余量，按 32 TOPS/盒向上取整。

### 点位与镜头估算

按「靶面 + 分辨率 + 监视距离 + 目标等级」反推镜头与安装方式，把"这个点位用什么镜头"从口头经验变成可复算的数：

- **视场与覆盖**：`FOV = 2·atan(靶面/2f)`，覆盖宽度 `W = 靶面 × 距离 ÷ f`。
- **像素密度**：`ρ = 像素数 × f ÷ (靶面 × 距离)`（px/m），直接和 DORI 判据比对。
- **DORI 判据**：监视 12.5 / 探测 25 / 观察 62.5 / 辨认 125 / 识别 250 px/m，按点位用途选档。
- **安装俯角**：`atan(安装高度 ÷ 距离)`，给出建议安装高度与俯角。
- **镜头推荐**：在标准定焦档（2.8 / 4 / 6 / 8 / 12 / 16 / 25 / 50 mm）里选满足密度要求的最小档，并给出"换档 或 缩短距离"两条可选建议。
- 热成像等无几何成像意义的产品自动跳过，不参与像素密度判定。

### GB/T 28181 接入预检

把"设备纳管前容易踩的坑"做成一条命令的自查清单：

- **国标 ID 校验**：20 位十进制，拆成 中心编码(8) + 行业编码(2) + 类型编码(3) + 网络标识(1) + 序号(6)；中心编码前 2 位按 GB/T 2260 省级行政区划校验，序号段为 0 判为无效。
- **类型编码校验**：取值随平台设备目录与行业约定不同，按配置文件给出的**允许集合**校验，不写成硬编码"标准"。
- **地址与端口**：IP 合法性、公网/私网（私网按 /24 去重提示）、`IP:端口` 重复、注册端口与媒体流接收段（默认 30000–30500）撞段。
- **容量核对**：通道总数与平台授权路数比对，超授权直接给缺口。
- **自动接入清单**：也能按场景点位一键生成国标 ID 与接入表，省掉手工编号。

### 规则引擎

不依赖检测模型即可离线复现，检测后端可插拔：

- **区域入侵**：射线法点在多边形内判定（`PolygonZone`）。
- **越界**：目标前后两帧中心点连线与警戒线求交（`LineZone`）。
- **类别合规**：按类别过滤 + 同一 track 的穿戴关联判定。
- **指标**：输出 TP / FP / FN、精确率、召回率、误报率。

|---|---|
| 场景模板 | 3 个（制造园区周界 16 路 / 高校校园 20 路 / 河道水利 14 路） |

| 单元测试 | 65 条，全部通过 |

## 四、快速开始

```bash
# 依赖
pip install -r requirements.txt

# 生成某一个场景的整套交付物
set PYTHONPATH=src
python -m wvp.cli generate --scenario config/scenarios/factory-perimeter.yaml

# 生成全部场景
python scripts/generate_all.py

# 按场景做点位与镜头估算
python -m wvp.cli optics --scenario config/scenarios/factory-perimeter.yaml

# 对设备接入清单做 GB/T 28181 预检
python -m wvp.cli gb28181-check --devices config/devices-demo.csv ^
    --types config/gb28181-device-types.yaml --platform-ch 16

# 跑规则引擎演示（含指标复算）
python -m wvp.cli rules-demo --rules config/rules-demo.yaml

# 单元测试
python -m pytest tests -q
```

新增场景只需在 `config/scenarios/` 下加一个 YAML（点位、规则、留存天数），重跑即可。

## 五、数据来源与口径

- 机型参数取自公开渠道可查的**通用规格档位**，用于方案测算，不引用任何厂商内部资料。
- `unit_price_ref` 为公开渠道档位参考价，仅用于 TCO 测算，不代表任何厂商正式报价。
- 规则引擎的指标基于 `config/rules-demo.yaml` 中的合成标注集，可完整复现。

---

## 六、局限

- 机型库是参数化抽象档位，不是具体产品目录，不能直接用于选型报价。
- 点位与镜头估算按理想几何模型计算，未计入畸变、逆光、雨雾与夜间补光对实际像素密度的影响。
- 接入预检按通用工程口径做自查，类型编码以配置文件为准；不替代平台侧实际注册与目录同步验证。
- 检测部分默认使用几何规则引擎以便离线复现；接入真实检测模型后事件判定链路不变，但准确率需重新标定。
- 极端天气、逆光、夜间等条件下的成像与检出表现无法在离线环境验证。
- TCO 只覆盖硬件、施工与运维三类，不含税费、专项吊装与运营商链路费用。
